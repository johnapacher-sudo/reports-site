OpenSpec "灵活、迭代式的规范驱动开发框架"

二、核心理念对比

2.1 GSD: 元提示 + 上下文工程

核心理念: "The complexity is in the system, not in your workflow."
         复杂性在系统中，而不是在你的工作流中。

核心问题: 上下文腐烂 (Context Rot)
         - 随着上下文窗口填满，输出质量下降
         - 每个 Plan 在全新的上下文窗口中执行
         - 保持主会话上下文清洁 (30-40%)

工作流:

讨论 → 计划 → 执行 → 验证
  ↓       ↓       ↓       ↓
/gsd:discuss → /gsd:plan → /gsd:execute → /gsd:verify

2.2 Superpower: Agent 技能增强

核心理念: "Makes Claude Code smarter, especially when running it in planning."
         让 Claude Code 变得更聪明，特别是在规划模式下。

核心方法: 提供专业的 Agent 技能
         - 增强规划能力
         - 提供专业领域知识
         - 优化决策过程

特点: - 作为 Claude Code 的插件运行 - 增强而非替代现有工作流 - 专注于提升智能度

2.3 OpenSpec: 规范驱动开发

核心理念: "Fluid not rigid, iterative not waterfall,
          easy not complex, built for brownfield not just greenfield"
         流动而非僵化，迭代而非瀑布，
         简单而非复杂，适用于棕地项目而非仅限绿地。

核心方法: 规范即真理 (Specification as Source of Truth)
         - /opsx:propose  提出变更
         - /opsx:apply    应用变更
         - /opsx:archive  归档规范

特点: - 支持 20+ AI 助手 - 适合现有项目 (brownfield) - 迭代式开发

3.2 核心功能详解

GSD 核心功能

命令 功能
/gsd:new-project 完整初始化：提问 → 研究 → 需求 → 路线图
/gsd:discuss-phase 在计划前捕获实现决策
/gsd:plan-phase 研究阶段 + 计划 + 验证
/gsd:execute-phase 并行分波执行所有计划
/gsd:verify-work 手动用户验收测试
/gsd:quick 快速模式执行临时任务

特色: - 原子 Git 提交（每个任务独立提交） - 多 Agent 并行执行 - 自动上下文管理

Superpower 核心功能

类型 功能
规划增强 更智能的任务分解
领域知识 专业领域的最佳实践
决策优化 更好的技术选型建议

特色: - 插件化设计 - 轻量级集成 - 无缝增强现有流程

OpenSpec 核心功能

命令 功能
/opsx:propose 提出功能规范或变更
/opsx:apply 根据规范实现代码
/opsx:archive 归档已完成的规范

特色: - 规范版本控制 - 支持现有项目 - 跨 AI 助手兼容

五、适用场景对比

5.1 GSD 最佳场景

场景 适用度 说明
新项目开发 ⭐⭐⭐⭐⭐ 完整的项目生命周期管理
复杂功能 ⭐⭐⭐⭐⭐ 多阶段、多 Agent 协作
长期项目 ⭐⭐⭐⭐⭐ 状态持久化，支持中断恢复
现有项目 ⭐⭐⭐ 支持 but 需要适配
快速原型 ⭐⭐⭐⭐ Quick 模式支持
简单任务 ⭐⭐ 可能过度工程化

典型用户: - 独立开发者 - 小团队 - 需要可靠 AI 辅助的人

5.2 Superpower 最佳场景

场景 适用度 说明
日常开发 ⭐⭐⭐⭐⭐ 无缝增强现有工作流
代码重构 ⭐⭐⭐⭐⭐ 专业建议和优化
技术选型 ⭐⭐⭐⭐ 更好的决策支持
新项目 ⭐⭐⭐ 可以但不专门针对
学习探索 ⭐⭐⭐⭐ 获得专业指导
团队协作 ⭐⭐⭐ 无特殊协作功能

典型用户: - Claude Code 日常用户 - 想要更智能输出的开发者 - 不想改变工作流的人

5.3 OpenSpec 最佳场景

场景 适用度 说明

功能迭代 ⭐⭐⭐⭐⭐ 迭代式开发流程
团队规范 ⭐⭐⭐⭐ 规范版本控制
多 AI 助手 ⭐⭐⭐⭐⭐ 支持 20+ 助手

典型用户: - 使用多种 AI 助手的团队 - 现有项目维护者 - 规范驱动的倡导者

七、优劣势分析

7.1 GSD

优势: - ✅ 完整的项目生命周期管理 - ✅ 解决上下文腐烂问题 - ✅ 多 Agent 并行执行 - ✅ 原子 Git 提交 - ✅ 丰富的命令系统 - ✅ 支持中断恢复

劣势: - ❌ 学习曲线相对较陡 - ❌ 对于简单任务可能过度 - ❌ 依赖 Node.js 生态 - ❌ 主要针对新项目

7.2 Superpower

优势: - ✅ 无缝集成，不改变习惯 - ✅ 学习曲线极低 - ✅ 自动增强输出质量 - ✅ 轻量级设计

劣势: - ❌ 仅支持 Claude Code - ❌ 功能相对有限 - ❌ 缺乏项目管理能力 - ❌ 无状态持久化

7.3 OpenSpec

优势: - ✅ 支持 20+ AI 助手 - ✅ 适合现有项目 - ✅ 迭代式，非瀑布式 - ✅ 规范版本控制 - ✅ 流程简单灵活

劣势: - ❌ 需要手动配置 - ❌ 缺乏自动化验证 - ❌ 无多 Agent 支持 - ❌ 社区相对较小

八、选型建议

    │
    └── 你需要处理复杂、长期的项目吗？

8.2 推荐组合

场景 推荐工具 原因
独立开发者新项目 GSD 完整生命周期管理
团队现有项目维护 OpenSpec 适合 brownfield
日常编码增强 Superpower 无缝集成
复杂功能开发 GSD 多 Agent 协作
快速原型验证 Superpower + GSD Quick 灵活组合
跨平台团队 OpenSpec 多助手支持

8.3 组合使用建议

GSD + Superpower:
- GSD 管理项目流程
- Superpower 增强每个步骤的输出质量

OpenSpec + Superpower:
- OpenSpec 管理规范
- Superpower 增强实现质量

不建议: GSD + OpenSpec
- 功能重叠较多
- 可能造成混乱

九、总结

9.1 核心差异总结

维度 GSD Superpower OpenSpec
定位 项目管理系统 能力增强插件 规范驱动框架
范围 全生命周期 单次交互 功能迭代
平台 多运行时 Claude only 跨平台
复杂度 中 低 低-中
最适合 新项目 日常开发 现有项目

9.2 最终建议

如果你是独立开发者，想要从零开始一个新项目:
  → 选择 GSD

如果你是 Claude Code 日常用户，想要更智能的输出:
  → 选择 Superpower

如果你维护现有项目，或使用多种 AI 助手:
  → 选择 OpenSpec

如果你想要最佳体验:
  → GSD + Superpower 组合使用
