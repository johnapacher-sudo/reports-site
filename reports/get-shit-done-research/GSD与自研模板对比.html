一、概览对比

维度 GSD 自研模板
定位 完整的规范驱动开发系统 轻量级长任务管理框架
复杂度 高 (功能丰富) 低 (简单直接)
依赖 Node.js + NPM Python 3 (标准库)
安装 npx get-shit-done-cc python3 init_long_task.py

集成方式 Claude Code Slash Commands 独立脚本 + 手动提示词

三、功能对比

3.1 项目初始化

功能 GSD 自研模板
命令 /gsd:new-project python3 init_long_task.py
交互方式 AI 问答式 模板选择
步骤生成 AI 动态生成 模板预设
研究阶段 ✅ 4个并行Agent研究 ❌ 无
需求文档 ✅ 自动生成 REQUIREMENTS.md ❌ 简单描述
路线图 ✅ 详细 ROADMAP.md ✅ task.json 中

GSD 初始化流程:

提问 (5-10分钟) → 研究 (并行Agent) → 需求 → 路线图 → 确认

自研模板初始化流程:

选择模板 → 生成文件 → 完成

3.2 阶段规划

功能 GSD 自研模板
讨论阶段 /gsd:discuss-phase (详细问答) 无
研究阶段 /gsd:plan-phase (包含研究) 无
计划生成 XML 格式 PLAN.md JSON 格式 task.json
计划验证 ✅ 自动验证计划可行性 ❌ 无
假设查看 /gsd:list-phase-assumptions ❌ 无

GSD 计划格式 (XML):

<task type="auto">
  <name>Create login endpoint</name>
  <files>src/app/api/auth/login/route.ts</files>
  <action>
    Use jose for JWT (not jsonwebtoken).
    Validate credentials against users table.
  </action>
  <verify>curl -X POST localhost:3000/api/auth/login returns 200</verify>
  <done>Valid credentials return cookie, invalid return 401</done>
</task>

自研模板计划格式 (JSON):

{
  "id": "setup",
  "description": "项目初始化",
  "tasks": ["创建目录", "初始化 Git"],
  "verification": {
    "type": "command",
    "command": "pip install -e ."
  },
  "status": "pending"
}

3.3 执行阶段

功能 GSD 自研模板
命令 /gsd:execute-phase N 手动复制提示词
执行方式 并行 Agent + 全新上下文 单一 Agent
上下文管理 ✅ 每个 Plan 200k 全新上下文 ❌ 共享上下文
并行执行 ✅ 独立计划并行 ❌ 顺序执行
Git 提交 ✅ 每个任务自动提交 ⚠️ 手动提交
执行总结 SUMMARY.md progress.md

3.4 验证阶段

功能 GSD 自研模板
命令 /gsd:verify-work python3 scripts/verify.py
验证类型 command, test, file_exists, manual command, test, file_exists, manual
失败诊断 ✅ 自动启动调试 Agent ❌ 手动处理
修复计划 ✅ 自动生成 ❌ 无

五、工作流对比

GSD 完整工作流

# 1. 初始化 (AI 问答 + 研究)
/gsd:new-project
> 回答 10+ 个问题...
> AI 研究技术栈...
> 审阅并确认路线图

# 2. 每个阶段循环
/gsd:discuss-phase 1      # 详细讨论实现细节
/gsd:plan-phase 1         # 研究 + 计划 + 验证
/gsd:execute-phase 1      # 并行执行 (自动)
/gsd:verify-work 1        # 用户验收测试

# 3. 完成里程碑
/gsd:complete-milestone
/gsd:new-milestone

自研模板工作流

# 1. 初始化 (模板选择)
python3 init_long_task.py "任务描述" --template cli-tool

# 2. 进入项目
cd task_xxx && ./init.sh

# 3. 生成提示词
python3 scripts/status.py --prompt

# 4. 复制提示词到 Claude Code

# 5. Claude 执行步骤

# 6. 验证
python3 scripts/verify.py --current

# 7. 重复 3-6

六、优缺点分析

GSD 优点

优点 说明
✅ 功能完整 覆盖项目全生命周期
✅ 深度集成 Claude Code Slash Commands
✅ 多 Agent 并行执行，全新上下文
✅ 自动研究 AI 自动研究技术栈
✅ 上下文工程 解决 context rot 问题
✅ XML 计划 结构化，验证内置
✅ 自动 Git 原子提交
✅ 失败诊断 自动调试 Agent

GSD 缺点

缺点 说明
❌ 复杂度高 学习曲线陡峭
❌ Token 消耗大 研究阶段消耗大量 Token
❌ 依赖 Node.js 需要 NPM 环境
❌ 启动慢 初始化需要 10+ 分钟
❌ 过度工程 小项目可能不需要

自研模板优点

优点 说明
✅ 轻量简单 只有 3 个脚本
✅ 无依赖 纯 Python 标准库
✅ 快速启动 一条命令完成初始化
✅ 统一文件 task.json 管理一切
✅ 灵活 可以自由修改
✅ 可定制 模板系统

自研模板缺点

缺点 说明
❌ 功能简单 缺少研究、讨论等阶段
❌ 无深度集成 需要手动复制提示词
❌ 单一 Agent 共享上下文
❌ 无并行 顺序执行
❌ 无自动 Git 需要手动提交
❌ 无失败诊断 需要手动处理

七、适用场景

选择 GSD 的场景

✅ 大型复杂项目
✅ 需要深度研究的领域
✅ 团队协作
✅ 长期维护的项目
✅ 对质量要求高
✅ 愿意投入 Token 成本
✅ 熟悉 Claude Code 生态系统

选择自研模板的场景

✅ 小型项目
✅ 快速原型
✅ 个人开发
✅ 简单任务
✅ Token 预算有限
✅ 想要轻量级方案
✅ 需要高度定制

十、整合建议

方案 1: 采用 GSD

如果你的需求： - 项目复杂度高 - 愿意投入学习时间 - Token 预算充足

npx get-shit-done-cc@latest
claude --dangerously-skip-permissions
/gsd:new-project

方案 2: 采用自研模板

如果你的需求： - 项目简单 - 快速上手 - 灵活定制

python3 init_long_task.py "任务描述"
cd task_xxx
python3 scripts/status.py --prompt

方案 3: 借鉴 GSD 改进自研模板

可以借鉴 GSD 的优点改进自研模板：

GSD 功能 如何借鉴
Slash Commands 创建 Claude Code 命令文件
XML 计划格式 改进 task.json 格式
自动 Git 添加 git_commit() 函数
验证失败诊断 添加 diagnose.py 脚本
快速任务 添加 quick.py 脚本

十一、总结

维度 GSD 自研模板
功能 ⭐⭐⭐⭐⭐ ⭐⭐
易用性 ⭐⭐ ⭐⭐⭐⭐⭐
灵活性 ⭐⭐⭐ ⭐⭐⭐⭐⭐
Token 效率 ⭐⭐ ⭐⭐⭐⭐
学习曲线 ⭐⭐ ⭐⭐⭐⭐⭐
适合大型项目 ⭐⭐⭐⭐⭐ ⭐⭐
适合小型项目 ⭐⭐⭐ ⭐⭐⭐⭐⭐

结论：

  • GSD = 功能强大的企业级解决方案，适合复杂项目
  • 自研模板 = 轻量灵活的个人工具，适合快速开发

两者并不冲突，可以根据项目规模选择合适的工具。
