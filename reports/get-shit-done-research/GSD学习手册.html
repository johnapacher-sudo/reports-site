一、快速开始

1.1 安装

打开终端，运行：

npx get-shit-done-cc@latest

安装程序会提示你选择：

? Select runtime:
  ❯ Claude Code
    OpenCode
    Gemini CLI
    All

? Install location:
  ❯ Global (~/.claude/) - Available in all projects
    Local (./.claude/) - Current project only

推荐选择： - Runtime: Claude Code - Location: Global (如果你想所有项目都可用)

1.2 验证安装

启动 Claude Code，输入：

/gsd:help

如果看到帮助信息，说明安装成功！

1.3 推荐启动方式

GSD 设计用于无摩擦自动化，推荐使用：

claude --dangerously-skip-permissions

这样 Claude 可以自动执行命令而不需要你反复确认。

二、核心概念

2.1 GSD 是什么？

GSD 是一个 规范驱动开发 (Spec-Driven Development) 系统：

你的想法 → GSD 提问 → 生成规范 → Claude 执行 → 验证完成

2.2 核心文件结构

GSD 会在项目中创建 .planning/ 目录：

your-project/
├── .planning/
│   ├── config.json          # GSD 配置
│   ├── PROJECT.md           # 项目愿景
│   ├── REQUIREMENTS.md      # 需求文档
│   ├── ROADMAP.md           # 开发路线图
│   ├── STATE.md             # 当前状态
│   ├── research/            # 研究文档
│   │   └── *.md
│   └── phases/              # 阶段文档
│       ├── phase-1-CONTEXT.md
│       ├── phase-1-RESEARCH.md
│       ├── phase-1-1-PLAN.md
│       ├── phase-1-1-SUMMARY.md
│       └── ...
└── src/                     # 你的代码

三、完整工作流教程

3.1 场景：开发一个待办事项 CLI 工具

让我们通过一个实际例子来学习 GSD。

Step 1: 创建项目目录

mkdir todo-cli
cd todo-cli

Step 2: 启动 Claude Code

claude --dangerously-skip-permissions

Step 3: 初始化项目

在 Claude Code 中输入：

/gsd:new-project

GSD 会开始提问：

🤖 GSD: 让我了解一下你的项目...

1. 你想构建什么？
   > 一个命令行待办事项工具

2. 你的主要目标是什么？
   > 能够添加、列出、完成和删除待办事项

3. 你偏好什么技术栈？
   > Python + Click 框架

4. 有什么特定的约束吗？
   > 数据存储在本地 JSON 文件中，不需要数据库

5. 这是 v1 版本还是更大项目的一部分？
   > 先做 v1，之后可能添加云同步功能

... 更多问题 ...

💡 提示：回答越详细，生成的规范越准确。不要害怕写长答案！

Step 4: 审阅路线图

GSD 会生成路线图：

📋 ROADMAP 生成完成！

Phase 1: 项目初始化
  - 创建项目结构
  - 配置 Click 框架
  - 设置数据存储

Phase 2: 核心功能
  - 实现 add 命令
  - 实现 list 命令
  - 实现 complete 命令
  - 实现 delete 命令

Phase 3: 测试与文档
  - 编写单元测试
  - 编写 README

是否批准此路线图？(y/n)

输入 y 继续。

Step 5: 讨论 Phase 1

/gsd:discuss-phase 1

GSD 会针对 Phase 1 提出更细节的问题：

🤖 关于项目初始化的一些细节：

1. 项目名称？
   > todo-cli

2. 需要虚拟环境吗？
   > 是的，使用 venv

3. 配置文件放在哪里？
   > ~/.todo-cli/config.json

4. 数据文件放在哪里？
   > ~/.todo-cli/todos.json

这些回答会被写入 phase-1-CONTEXT.md。

Step 6: 计划 Phase 1

/gsd:plan-phase 1

GSD 会： 1. 研究 Python CLI 最佳实践 2. 生成 2-3 个具体的执行计划（PLAN.md）

📝 生成的计划：

Plan 1-1: 创建项目结构
  - 创建 todo_cli/ 目录
  - 创建 __init__.py
  - 创建 main.py 入口

Plan 1-2: 配置 Click 和数据存储
  - 安装 click 依赖
  - 创建 storage.py
  - 实现 JSON 读写

验证通过 ✓

Step 7: 执行 Phase 1

/gsd:execute-phase 1

这一步会自动执行！ GSD 会： - 启动多个并行 Agent - 每个 Agent 执行一个计划 - 自动提交 Git commit

🚀 执行 Phase 1...

[Agent 1] 执行 Plan 1-1...
          ✓ 创建 todo_cli/ 目录
          ✓ 创建 __init__.py
          ✓ 创建 main.py
          ✓ Git commit: feat: 初始化项目结构

[Agent 2] 执行 Plan 1-2...
          ✓ 安装 click
          ✓ 创建 storage.py
          ✓ 实现 JSON 读写
          ✓ Git commit: feat: 添加数据存储功能

✅ Phase 1 执行完成！

Step 8: 验证工作

/gsd:verify-work 1

GSD 会引导你测试：

🧪 让我们验证 Phase 1 的功能：

1. 运行 `python -m todo_cli --help`
   能看到帮助信息吗？(y/n/describe issue)
   > y ✓

2. 检查 ~/.todo-cli/ 目录是否存在
   存在吗？(y/n/describe issue)
   > y ✓

✅ Phase 1 验证通过！

如果有问题，输入 describe issue 描述问题，GSD 会自动诊断并生成修复计划。

Step 9: 重复 Phase 2-3

/gsd:discuss-phase 2
/gsd:plan-phase 2
/gsd:execute-phase 2
/gsd:verify-work 2

/gsd:discuss-phase 3
/gsd:plan-phase 3
/gsd:execute-phase 3
/gsd:verify-work 3

Step 10: 完成里程碑

/gsd:complete-milestone

GSD 会： - 归档所有计划文档 - 创建 Git tag (如 v1.0.0) - 询问是否开始下一个里程碑

四、命令详解

4.1 核心工作流命令

/gsd:new-project - 初始化新项目

用途：开始一个全新的项目

流程：

提问 → 研究 → 需求 → 路线图 → 确认

生成的文件： - PROJECT.md - 项目愿景和目标 - REQUIREMENTS.md - v1/v2 需求划分 - ROADMAP.md - 开发阶段规划 - STATE.md - 项目状态跟踪 - .planning/research/ - 研究文档

示例：

/gsd:new-project

💡 技巧：如果已有代码库，先运行 /gsd:map-codebase！

/gsd:discuss-phase [N] - 讨论阶段

用途：在计划前细化实现细节

参数： - N - 阶段编号（可选，默认当前阶段）

生成文件： - phase-N-CONTEXT.md - 上下文决策

问题类型： | 功能类型 | 问题示例 | |---------|---------| | 视觉功能 | 布局样式？密度？空状态？ | | API/CLI | 输出格式？错误处理？ | | 内容系统 | 结构？语调？深度？ |

示例：

/gsd:discuss-phase 1
/gsd:discuss-phase    # 自动使用当前阶段

/gsd:plan-phase [N] - 计划阶段

用途：研究和制定执行计划

参数： - N - 阶段编号 - --skip-research - 跳过研究阶段 - --skip-verify - 跳过计划验证

流程：

研究 → 计划 → 验证 → 循环直到通过

生成文件： - phase-N-RESEARCH.md - 研究结果 - phase-N-1-PLAN.md - 第 1 个计划 - phase-N-2-PLAN.md - 第 2 个计划 - ...

示例：

/gsd:plan-phase 1
/gsd:plan-phase 2 --skip-research

/gsd:execute-phase <N> - 执行阶段

用途：自动执行所有计划

参数： - N - 阶段编号（必需）

执行方式： - 独立计划 → 并行执行 - 依赖计划 → 顺序执行

每个计划： - 在全新的 200k 上下文中执行 - 执行完立即 Git commit

生成文件： - phase-N-X-SUMMARY.md - 执行总结 - phase-N-VERIFICATION.md - 验证结果

示例：

/gsd:execute-phase 1

⚠️ 注意：执行前确保你已经审阅了计划！

/gsd:verify-work [N] - 验证工作

用途：手动验收测试

参数： - N - 阶段编号（可选）

流程： 1. GSD 提取可测试的交付物 2. 逐个引导你测试 3. 记录通过/失败 4. 失败时自动诊断并生成修复计划

生成文件： - phase-N-UAT.md - 用户验收测试结果 - 修复计划（如果失败）

示例：

/gsd:verify-work 1

/gsd:complete-milestone - 完成里程碑

用途：归档当前里程碑

操作： - 归档所有计划文档 - 创建 Git tag - 询问是否 squash merge

示例：

/gsd:complete-milestone

/gsd:new-milestone [name] - 新建里程碑

用途：开始下一个版本

参数： - name - 里程碑名称（可选）

流程：与 new-project 类似，但基于现有代码库

示例：

/gsd:new-milestone v2.0

4.2 导航命令

/gsd:progress - 查看进度

用途：了解当前状态和下一步

输出示例：

📊 项目进度

当前状态：执行中
当前阶段：Phase 2 - 核心功能
完成进度：2/3 阶段 (67%)

下一步：
  /gsd:verify-work 2  - 验证 Phase 2

/gsd:help - 帮助

用途：显示所有命令

/gsd:update - 更新

用途：更新 GSD 到最新版本

4.3 Brownfield 命令

/gsd:map-codebase - 映射代码库

用途：在已有代码库中使用 GSD 前运行

操作： - 启动并行 Agent 分析代码库 - 分析技术栈、架构、约定、关注点 - 生成代码库映射

何时使用：

✅ 已有项目，想用 GSD 继续开发
✅ 继承了他人的代码库
✅ 想了解一个陌生的项目

❌ 全新项目（不需要）

示例：

/gsd:map-codebase

4.4 阶段管理命令

/gsd:add-phase - 添加阶段

用途：在路线图末尾添加新阶段

/gsd:insert-phase [N] - 插入阶段

用途：在阶段 N 之前插入新阶段

示例：

/gsd:insert-phase 2   # 在 Phase 2 前插入

/gsd:remove-phase [N] - 删除阶段

用途：删除未执行的阶段

示例：

/gsd:remove-phase 3

4.5 会话命令

/gsd:pause-work - 暂停工作

用途：中途停止时创建交接文档

生成文件： - HANDOFF.md - 交接文档

/gsd:resume-work - 恢复工作

用途：从上次停止的地方继续

4.6 实用工具命令

/gsd:quick - 快速任务

用途：执行不需要完整规划的小任务

适用场景： - Bug 修复 - 小功能添加 - 配置更改 - 一次性任务

示例：

/gsd:quick
> What do you want to do? 添加深色模式开关

/gsd:add-todo [desc] - 添加待办

用途：捕获想法供以后使用

示例：

/gsd:add-todo 考虑添加导出功能

/gsd:check-todos - 查看待办

用途：列出所有待处理的 todos

/gsd:debug [desc] - 调试

用途：系统性调试问题

特点：带持久状态的调试流程

/gsd:settings - 配置

用途：配置模型配置和工作流 Agent

/gsd:set-profile <profile> - 设置模型

用途：切换模型配置

选项： | Profile | 规划 | 执行 | 验证 | |---------|------|------|------| | quality | Opus | Opus | Sonnet | | balanced | Opus | Sonnet | Sonnet | | budget | Sonnet | Sonnet | Haiku |

示例：

/gsd:set-profile quality

五、配置指南

5.1 配置文件位置

.planning/config.json

5.2 核心设置

{
  "mode": "interactive",
  "depth": "standard"
}
设置 选项 说明
mode interactive / yolo 交互式 vs 自动批准
depth quick / standard / comprehensive 计划详细程度

5.3 模型配置

{
  "profile": "balanced",
  "models": {
    "planning": "opus",
    "execution": "sonnet",
    "verification": "sonnet"
  }
}

5.4 工作流 Agent

{
  "workflow": {
    "research": true,       // 计划前研究领域
    "plan_check": true,     // 验证计划是否满足目标
    "verifier": true        // 执行后验证交付物
  }
}

5.5 Git 分支策略

{
  "git": {
    "branching_strategy": "none",  // none / phase / milestone
    "phase_branch_template": "gsd/phase-{phase}-{slug}",
    "milestone_branch_template": "gsd/{milestone}-{slug}"
  }
}

策略说明： - none - 直接在当前分支提交 - phase - 每个阶段创建分支 - milestone - 每个里程碑创建分支

七、常见问题

Q1: 命令找不到？

原因：Claude Code 没有重新加载命令

解决： 1. 重启 Claude Code 2. 检查文件是否存在：~/.claude/commands/gsd/ 3. 重新安装：npx get-shit-done-cc@latest

Q2: Token 消耗太多？

原因：GSD 的研究阶段会消耗较多 Token

解决：

# 使用 budget 配置
/gsd:set-profile budget

# 跳过研究阶段
/gsd:plan-phase 1 --skip-research

Q3: 执行结果不符合预期？

原因：discuss-phase 不够详细

解决： 1. 在 discuss-phase 提供更多细节 2. 在 plan-phase 仔细审阅计划 3. 使用 /gsd:list-phase-assumptions 1 查看 Claude 的假设

Q4: 想修改已生成的计划？

解决：

# 直接编辑 PLAN.md 文件
# 然后
/gsd:execute-phase 1

Q5: 如何在团队中使用？

建议： 1. .planning/ 目录提交到 Git 2. 团队成员可以查看和编辑计划 3. 使用 milestone 分支策略避免冲突

八、最佳实践

8.1 提问阶段

✅ 好的回答：

> 一个命令行工具，支持添加、列出、完成、删除待办事项。
> 数据存储在本地 JSON 文件，不需要数据库。
> 使用 Python + Click 框架。
> 命令风格类似 git：todo add "任务名"

❌ 不好的回答：

> 一个 todo 工具

8.2 Discuss 阶段

✅ 详细描述偏好：

> 列表显示：编号、任务名、状态、创建时间
> 状态用颜色区分：绿色=完成，黄色=进行中
> 支持按状态筛选

8.3 Plan 阶段

✅ 仔细审阅计划：

# 检查要点：
1. 技术选型是否正确？
2. 是否遗漏了功能？
3. 验证步骤是否合理？

8.4 Execute 阶段

✅ 执行前准备：

1. 确保工作目录干净（git status）
2. 审阅所有计划
3. 预留足够时间（不要中途打断）

8.5 Verify 阶段

✅ 认真测试：

1. 按照引导逐项测试
2. 不要跳过任何检查项
3. 发现问题详细描述

8.6 日常使用

# 每日开始
/gsd:progress          # 查看进度
/gsd:resume-work       # 恢复工作

# 每日结束
/gsd:pause-work        # 保存进度

# 捕获想法
/gsd:add-todo 考虑添加导出功能

# 快速任务
/gsd:quick

十、总结

GSD 的核心价值：

  1. 结构化 - 强制你先思考再编码
  2. 自动化 - Claude 自动执行，你只需验证
  3. 可靠性 - 解决上下文腐烂问题
  4. 可追溯 - 每个任务都有原子提交

记住：

"The complexity is in the system, not in your workflow." 复杂性在系统中，而不是在你的工作流中。
