1.2 一句话介绍

Agency Swarm 是一个基于 OpenAI Agents SDK 构建的多智能体编排框架，提供可定制的智能体角色、完全的提示词控制、类型安全的工具定义和编排化的通信机制。

1.3 发展历程

2024年初  → 项目启动，基于 OpenAI Assistants API
2024年中  → 迁移至 OpenAI Agents SDK
2025年    → 支持 GPT-5、多模型路由、生产级稳定性
现在      → 持续迭代，社区活跃

1.4 核心定位

Agency Swarm 的定位是：
  "Production-ready multi-agent framework built on OpenAI Agents SDK"

与传统框架的区别：
  - CrewAI: 强调角色扮演和任务协作，但控制粒度较粗
  - LangGraph: 基于状态图，适合复杂工作流但学习曲线陡峭
  - Agency Swarm: 基于 OpenAI 原生 SDK，提示词完全可控，通信编排化

2.2 核心功能详解

2.2.1 自定义智能体 (Agent)

from agency_swarm import Agent, ModelSettings

ceo = Agent(
    name="CEO",
    description="负责客户沟通、任务规划和管理。",
    instructions="你必须与其他智能体协作确保任务完整执行。",
    tools=[my_custom_tool],
    model="gpt-5.2",
    model_settings=ModelSettings(
        temperature=0.7,
        max_tokens=4096
    )
)

关键属性： | 参数 | 类型 | 说明 | |------|------|------| | name | str | 智能体名称（唯一标识） | | description | str | 角色描述 | | instructions | str | 详细指令 | | tools | list | 可用工具列表 | | model | str | 使用的模型 | | model_settings | ModelSettings | 模型参数配置 |

2.2.2 通信流编排 (Communication Flows)

from agency_swarm import Agency

agency = Agency(
    ceo,  # 入口智能体
    communication_flows=[
        ceo > dev,      # CEO 可以发给 Developer
        ceo > va,       # CEO 可以发给 Virtual Assistant
        dev > va        # Developer 可以发给 Virtual Assistant
    ],
    shared_instructions='agency_manifesto.md'
)

通信规则： - 使用 > 运算符定义方向性通信 - 只能单向发送消息（A > B 表示 A 可以发消息给 B） - 入口智能体接收用户的初始请求

2.2.4 状态持久化

def load_threads_callback():
    """加载保存的线程状态"""
    with open('threads.json', 'r') as f:
        return json.load(f)

def save_threads_callback(threads):
    """保存线程状态"""
    with open('threads.json', 'w') as f:
        json.dump(threads, f)

agency = Agency(
    ceo,
    communication_flows=[ceo > dev],
    load_threads_callback=load_threads_callback,
    save_threads_callback=save_threads_callback
)

5.2 典型用例

用例 1: 软件开发团队

from agency_swarm import Agent, Agency, function_tool

# 定义工具
@function_tool
def create_file(filename: str, content: str) -> str:
    """创建文件并写入内容"""
    with open(filename, 'w') as f:
        f.write(content)
    return f"文件 {filename} 创建成功"

# 定义角色
architect = Agent(
    name="Architect",
    description="负责系统架构设计和技术决策",
    instructions="你是一位资深架构师，负责设计系统架构..."
)

developer = Agent(
    name="Developer",
    description="负责代码实现",
    instructions="你是一位全栈开发者...",
    tools=[create_file]
)

tester = Agent(
    name="Tester",
    description="负责测试和质量保证",
    instructions="你是一位测试工程师..."
)

# 创建编排
agency = Agency(
    architect,
    communication_flows=[
        architect > developer,
        developer > tester
    ]
)

# 执行任务
response = await agency.get_response("创建一个待办事项 API")

用例 2: 内容创作团队

editor = Agent(name="Editor", description="内容策划和编辑")
writer = Agent(name="Writer", description="内容撰写")
reviewer = Agent(name="Reviewer", description="内容审核")

agency = Agency(

5.3 不适用场景

场景 原因 替代方案

实时对话 编排延迟较高 使用 WebSocket + 单智能体
简单脚本 复杂度不匹配 使用普通脚本
大规模并发 API 调用成本高 考虑缓存和批处理

六、最佳实践

6.1 智能体设计原则

1. 单一职责
   - 每个智能体专注于一个领域
   - 避免全能型智能体

2. 清晰边界
   - 明确每个智能体的职责边界
   - 避免职责重叠

3. 适度粒度
   - 不是越多智能体越好
   - 3-5 个智能体通常足够

4. 有效沟通
   - 定义清晰的通信流
   - 避免循环依赖

6.2 通信流设计

# ✅ 好的设计：层级清晰
communication_flows=[
    ceo > manager,
    manager > developer,
    manager > designer
]

# ❌ 避免的设计：过于复杂
communication_flows=[
    a > b, b > c, c > d, d > e,
    a > c, a > d, b > d, b > e
]

6.5 错误处理

import asyncio
from agency_swarm import Agency

async def run_with_retry(agency, message, max_retries=3):
    """带重试的执行"""
    for attempt in range(max_retries):
        try:
            response = await agency.get_response(message)
            return response
        except Exception as e:
            print(f"尝试 {attempt + 1} 失败: {e}")
            if attempt == max_retries - 1:
                raise
            await asyncio.sleep(2 ** attempt)  # 指数退避

    return None

八、总结

  • ❌ 高级特性需要深入了解 OpenAI SDK
